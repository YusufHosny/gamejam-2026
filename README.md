# gamejam-2026

A rhythm game about the last five minutes before a game jam deadline. You have 5:00:000 left to submit and everything goes wrong. The game cycles through short rhythm minigames, each using a different input style, while a deadline clock counts down in the corner.

Built with **Godot 4.7** (GDScript, Forward Plus).

## Running

Open the folder in Godot 4.7 and press F5, or run it from the command line:

```sh
godot --path .
```

The main scene is `scenes/main.tscn`. Prototype scenes in `scenes/prototypes/` can be run on their own with F6 (Run Current Scene).

## Controls

| Action | Default binding |
| --- | --- |
| 4D lanes | `Z` `X` `N` `M` |
| Click (aim minigame) | `Z` / `X`, or left / right mouse button |
| Release captured mouse | `Esc` (click to capture it again) |
| Restart | `F5` |
| Debug: skip to a minigame | `F1` 4D, `F2` aim + click, `F3` slash, `F4` typing |

Keybinds are defined in `GameConfig.keybinds` and use physical keys, so the lanes stay in the same place on AZERTY, Dvorak and other layouts. `GameConfig.rebind()` changes them at runtime.

## How a run plays

1. **Intro.** 5:00:000 flashes red with an alarm, then shrinks into the top-right corner (`DeadlineClock.play_intro()`). Gameplay and input are paused until this finishes.
2. **Song.** The conductor starts and the chart plays from start to finish. The chart is a list of **segments**, and each segment is one minigame.
3. **Cooldowns.** Before each segment there is a short gap. During the gap a banner blinks on the beat showing the hand position the next minigame needs:
   - **A**: right hand on the mouse, left hand on the keys (aim + click, slash)
   - **B**: both hands on the keys (4D, typing)
4. **Deadline clock.** The clock shows `GameConfig.deadline_s - song_time`. It runs on the song clock, not a separate timer, so a given moment in the chart always shows the same time left.

## Minigames

| Mode | Hand pos | How to play |
| --- | --- | --- |
| **4D** (`FourDMode`) | B | Notes scroll down four lanes. Press the lane key when a note reaches the receptor. |
| **Aim + click** (`AimClickMode`) | A | osu!-style circles with shrinking approach rings. Put the cursor on the circle and click on the beat. Clicking anywhere else counts as a miss. |
| **Slash** (`SlashMode`) | A | Same circles, but you hit them by swiping the cursor through them faster than `GameConfig.slash_min_speed`. |
| **Typing** (`TypingMode`) | B | Words scroll past a caret. Type each letter on the beat. A wrong letter counts as a miss. |

## Architecture

### Timing: `Conductor`

`Conductor` (an `AudioStreamPlayer`) is the only clock used for gameplay. `song_time()` is computed from the audio playback position, corrected for output latency and `GameConfig.audio_offset_ms`. It is never based on frame time. Anything that needs to stay in sync with the music (judging, note drawing, the deadline clock) should read `conductor.song_time()`.

At the moment the "song" is a metronome generated by `SfxUtils.metronome()`, sized to the chart length.

### Charts: `Chart`, `ChartSegment`, `Note`

- A `Chart` has a `bpm`, a `beats_per_bar` and a sorted list of non-overlapping `ChartSegment`s.
- Each segment has a `kind` (`Modality.Kind`), a `start_beat` / `end_beat`, and its notes. The gap before `start_beat` is the cooldown.
- Notes are authored in beats. `Chart.bake()` converts beats to seconds (`time`, `start_time`, `end_time`). Call it after building or editing a chart.
- Note subclasses store what their mode needs: `LaneNote.lane`, `AimNote.position`, `LetterNote.letter` / `space_before`.

`DemoChart.build()` generates a chart procedurally from `ORDER`, using a seeded RNG (`GameConfig.chart_seed`), so the same seed always produces the same chart. Typing words come from `WordList`.

### Game loop: `Game`

Every frame, `Game._process()`:

1. reads `song_time`,
2. updates the deadline clock,
3. asks the chart which segment is active (`Chart.segment_at`) and calls `begin()` / `end()` on the mode handlers when it changes,
4. shows or hides the hand-position banner during cooldowns.

`Game` also handles restarts, debug seeking and passing judgements to `ScoreKeeper` and the HUD.

### Minigames: `ModeHandler`

Every minigame extends the abstract `ModeHandler`:

- `begin(segment)` / `end()` activate the handler and show or hide it.
- The base `_process()` automatically misses notes once they pass the miss window.
- Subclasses implement `_handle_input(event, now)` and call `_hit(note, now)` or `_resolve(HitResult.miss(note))`.
- Every result goes out through the `judged` signal.
- `TargetMode` is the shared base for the two circle modes (approach-ring drawing).

Mouse modes use `VirtualCursor` instead of the OS cursor. It captures the mouse so `GameConfig.mouse_sensitivity` can be applied.

### Judging and scoring

- `Judgement.grade()` grades the absolute timing error against `GameConfig.hit_windows_ms`: GREAT 40 ms, OK 90 ms, MEH 135 ms, otherwise a miss. The MEH window is also the miss window.
- `ScoreKeeper` uses osu! v1-style scoring (hit value × combo multiplier) and tracks accuracy.
- `HitResult.error_s` is negative for early hits and positive for late ones. `TimingBar` plots it.

### HUD

`Hud` is a `CanvasLayer` that only displays what `Game` passes to it: score, accuracy, combo, the judgement popup, the timing bar, the current hand-position icon, the cooldown banner and the `DeadlineClock`.

## USB animation (prototype)

The USB animation is a GIF of someone failing to plug in a USB. Each press plays the next part of it, so it can later be tied to a minigame input or the beat. It isn't part of the main game yet.

- **Try it:** open `scenes/prototypes/usb_test.tscn` and press F6. Every key press or click plays the next phase.
- **Phases:** arrow → push → bump ×4 → flip + arrow → push → bump ×3 → flip back, then it loops. The plug never actually goes in, which is the joke.
- **`UsbAnimation`** (`scripts/ui/usb_animation.gd`) is a `Sprite2D`:
  - `advance()` plays the next phase.
  - `phase_finished(phase)` fires when a phase ends.
  - `speed` scales playback.
  - Presses made while a phase is still playing are queued, and the animation speeds up to catch up.
- **Re-splitting the phases:** edit `PHASE_ENDS`, which holds the last GIF frame of each phase (the GIF has 149 frames at 60 ms each).
- **Spritesheet:** Godot can't import GIFs, so `assets/usb.gif` is converted to `assets/usb_sheet.png` (a 10 × 15 grid, VRAM compressed) with:

  ```sh
  python3 tools/gif_to_sheet.py assets/usb.gif assets/usb_sheet.png
  ```

  The script prints the `hframes` / `vframes` values to set on the `Sprite2D`. Set its `texture_filter` to linear, because the project default (nearest) is meant for pixel art.

## Adding a minigame

1. Add a value to `Modality.Kind` and map it to a hand position in `Modality.hand_pos()`.
2. If the mode needs extra data, add a `Note` subclass for it.
3. Create `scripts/modes/<name>_mode.gd` extending `ModeHandler` (or `TargetMode`) and implement `_handle_input` and `_draw`.
4. Add a node for it under `Modes` in `main.tscn`. In `Game`, add an `@onready` reference to it, add it to the handler list in `_ready()`, add it to `_handler()` and optionally add a debug seek.
5. Generate its notes in `DemoChart._notes()` and add it to `DemoChart.ORDER`.

## Tuning (`GameConfig`)

`GameConfig` is an autoload, so all tuning values live in one place:

| Setting | Meaning |
| --- | --- |
| `audio_offset_ms` | Global calibration. A positive value judges notes later. |
| `hit_windows_ms` | Timing window for each grade. |
| `approach_time_s` | How early circles and letters appear. |
| `scroll_speed` | 4D note speed in px/s. |
| `bpm`, `segment_bars`, `cooldown_bars`, `chart_seed` | Shape of the demo chart. |
| `deadline_s` | Length of the whole run, as shown on the deadline clock. |
| `mouse_sensitivity`, `slash_min_speed` | Mouse feel. |

## Current status / known gaps

- **Chart length vs. deadline.** The demo chart is 8 × (2 + 8) bars at 120 BPM, about 2:40. When the song ends the clock freezes at about 2:20 instead of reaching 0. For a full 5:00 at 120 BPM, segments plus cooldowns should add up to 150 bars.
- **Nothing happens at 0:00:000** yet: there is no win/lose screen.
- **Audio is a placeholder.** The metronome, hitsound and alarm are synthesized in `SfxUtils`. Real music and SFX still need to be added.
- **`scenes/devices/`** (computer and phone frames) aren't used yet. They're meant as in-world screens for the minigames.
- **No results screen, menu or settings UI.**
- **The USB animation** only exists in a prototype scene. Which input it should respond to hasn't been decided yet.
